# ویراستار پژوهش — نسخهٔ ۲.۱

ربات بله و ابزار خط فرمان برای بازبینی غیرمخرب اسناد پژوهشی فارسی و انگلیسی. سامانه متن را بازنویسی نمی‌کند؛ یافته، شاهد، محل و پیشنهاد بازبینی ارائه می‌دهد. نتیجهٔ این بررسی تأیید صحت علمی یا تضمین نبود خطا نیست.

## قابلیت‌ها

- تحلیل Word شامل متن اصلی، جدول‌های تو‌در‌تو، سرصفحه و پاصفحه، پاورقی و پی‌نوشت، و متن‌کادرهای قابل استخراج؛ همراه با شناسهٔ بلوک و مسیر XML.
- بررسی صفحه‌به‌صفحهٔ PDF؛ متن کوتاه حذف نمی‌شود و صفحات بدون متن یا مشکوک جداگانه مشخص می‌شوند. OCR انجام نمی‌شود.
- قواعد فارسی، نگارش دانشگاهی، انگلیسی و سازگاری ارجاع، با تفکیک اطمینان بالا، بازبینی و ابهام؛ اطمینان یک احتمال آماری نیست.
- حفاظت از اعداد، واحدهای مرکب، فرمول، نماد، DOI، نشانی ایمیل و کد؛ نرمال‌سازی فقط برای تحلیل و با نگاشت به متن اصلی است.
- گزارش HTML آفلاین با جست‌وجو، فیلتر و چاپ، و خروجی JSON، CSV و متن. CSV در برابر اجرای فرمول از متن منبع محافظت می‌شود.
- خروجی پیش‌فرض Word با هایلایت و کامنت کوتاه، تطبیق دقیق و حفظ اجزای بسته؛ منبع و شیء سند فراخواننده بازنویسی نمی‌شوند.
- خلاصهٔ کوتاه A/B/C و تعداد واقعی کامنت‌ها؛ علت درج‌نشدن هر مورد در گزارش کامل ثبت می‌شود.
- اولویت سراسری A سپس B، سقف پیش‌فرض ۲۵۰ کامنت قابل تنظیم؛ C در حالت پیش‌فرض فقط برای بررسی دستی است.
- صف محدود مشترک برای متن و فایل، تثبیت حالت در زمان ثبت درخواست، کنترل درخواست تکراری و توقف مرتب.
- بررسی امضای فایل، بودجهٔ ZIP/XML و متن، تعداد یافته‌ها، مسیر خروجی و هش ورودی.

## اجرا

Python 3.12 یا جدیدتر و وابستگی‌های requirements.txt لازم‌اند. آزمون محلی این تغییرات با Python 3.14.6 انجام شده است؛ اجرای ماتریس CI به محیط GitHub وابسته است.

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
```

فایل .env.example را به .env کپی و BALE_TOKEN را با توکن خود تنظیم کنید. سپس:

```powershell
.venv\Scripts\python bot.py
```

Linux:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python bot.py
```

فایل Word را بفرستید؛ کپی «نسخهٔ بازبینی» بدون نیاز به `/annotate` برمی‌گردد. پیشنهادها در متن اعمال نمی‌شوند. `/comments` راهنمای دیدن کامنت‌ها و `/report` گزارش کامل HTML و TXT آخرین بررسی شما را می‌فرستد. برای یک قالب از `/report html` یا `/report txt` و برای حذف گزارش نگهداری‌شده از `/forget` استفاده کنید. PDF به‌صورت پیش‌فرض گزارش متنی صفحه‌دار دارد.

دستورات انتخاب حالت: `/thesis`، `/tums`، `/article` و `/english`. انتخاب حالت در زمان ثبت درخواست حفظ می‌شود، حتی اگر در زمان انتظار حالت را تغییر دهید. `/settings` محدودیت‌ها، `/privacy` نگهداری داده و `/help` راهنما را نشان می‌دهد.

## خط فرمان و گزارش‌ها

```powershell
python checker.py thesis.docx --mode thesis --output-dir reports
python checker.py article.pdf --mode article --format json
python checker.py paragraph.txt --text --mode english --output-dir reports
python checker.py thesis.docx --annotate reviewed.docx
python checker.py thesis.docx --annotate reviewed.docx --max-comments 100
python checker.py article.pdf --annotate-pdf reviewed.pdf --output-dir reports
python checker.py --list-rules
python checker.py --version
```

پوشهٔ خروجی شامل report.html، report.json، report.csv و report.txt است. مسیر خروجی نمی‌تواند همان ورودی یا پیوندی به آن باشد. `--rules custom-rules.json` قواعد سفارشی، `--include-ambiguous` نمایش ابهام و `--fail-on A` کد خروج مناسب خودکارسازی را فراهم می‌کند. کد خروج ۰ موفقیت، ۱ یافتهٔ سطح انتخابی و ۲ خطای پردازش است.

`--annotate-pdf` آزمایشی است: فقط شاهدی با نگاشت دقیق نویسه و مختصات نشانه‌گذاری می‌شود. آزمون‌های متن شکل‌یافتهٔ فارسی، نیم‌فاصله، اعراب، متن دوزبانه، تکرار، ستون و چرخش انجام می‌شوند؛ نمایش یادداشت فارسی در PDFخوان‌های مستقل هنوز تأیید نشده است. برای ربات، `PDF_ANNOTATION_EXPERIMENTAL=0` پیش‌فرض می‌ماند و گزارش متنی صفحه‌دار حفظ می‌شود.

[نمونهٔ محلی گزارش HTML با دادهٔ مصنوعی](docs/demo/report.html) · [گزارش کامل ارتقا](docs/PROFESSIONAL_UPGRADE.md)

برای ساخت بستهٔ کد بدون .env، اسناد عملیاتی، تاریخچهٔ Git و پشتیبان‌ها، `python package_release.py` را اجرا کنید. فایل ZIP در dist ساخته می‌شود و manifest هش دارد. نمونه‌های اسنادی demo و PDF شیوه‌نامه به بستهٔ کد وارد نمی‌شوند.

## پیکربندی

مقادیر محیطی در .env.example توضیح داده شده‌اند. MAX_QUEUE تعداد انتظار علاوه بر WORKERS است. تعداد کل درخواست‌های ثبت‌شده از مجموع این دو بیشتر نمی‌شود. هیچ فایل یا متن کاربری در لاگ یا پاسخ سلامت قرار نمی‌گیرد.

`MAX_COMMENTS=250` سقف کامنت Word را تعیین می‌کند (۱ تا ۱۰۰۰). در مسیر ربات سقف جداگانهٔ پاراگراف فعال نیست. `REPORT_TTL_MINUTES=15`، `REPORT_CACHE_MB=32` و سقف داخلی ۶۴ گزارش/۸ مگابایت برای هر گزارش، نگهداری را محدود می‌کنند. فقط HTML و TXT در حافظه نگهداری می‌شوند و دسترسی به ترکیب فرستنده و گفت‌وگو محدود است. بررسی جدید جای گزارش قبلی همان فرستنده را می‌گیرد. گزارش منقضی قابل دریافت نیست؛ پاک‌سازی حافظه هر ۳۰ ثانیه انجام می‌شود. پرشدن ظرفیت یا راه‌اندازی مجدد ممکن است گزارش را زودتر پاک کند. اگر گزارش بزرگ‌تر از ظرفیت باشد، همان لحظه ارسال می‌شود تا نتیجه بی‌صدا از دست نرود.

قواعد در rules.json و پروفایل دانشگاه در profiles/tums.json نگهداری می‌شوند. کلیدهای اختیاری:

| کلید | پیش‌فرض | کاربرد |
|---|---:|---|
| strict | true | خودداری از نمایش عادی موارد مبهم |
| protected_terms | [] | نام و اصطلاح تخصصی که نباید پیشنهاد عمومی دریافت کند |
| disabled_rules | [] | شناسهٔ قواعد غیرفعال، در همهٔ خروجی‌های تحلیل |
| max_input_bytes | 26214400 | سقف اندازهٔ ورودی |
| max_document_chars | 4000000 | بودجهٔ متن سند |
| max_document_blocks | 25000 | بودجهٔ بلوک‌های Word |
| max_analysis_block_chars | 200000 | بودجهٔ هر بلوک قواعد |
| max_findings_per_block | 500 | سقف یافتهٔ هر بلوک، همراه هشدار محدودیت |
| max_findings | 10000 | سقف یافتهٔ سند، همراه هشدار محدودیت |
| max_pdf_pages | 1000 | بودجهٔ صفحات PDF |

کلیدهای متنی/اندازه‌ای مهم هنگام بارگذاری اعتبارسنجی می‌شوند. تنظیمات سفارشی باید ساختار کامل قواعد پایه را حفظ کنند. حذف یک هشدار از خروجی به معنی درست‌بودن متن نیست.

## آزمون و استقرار

نسخهٔ ۲.۱ خروجی پیش‌فرض Word، گزارش اختیاری با دسترسی محدود، کامنت‌های کوتاه و اولویت‌دار، گزارش کامل بدون سقف پنهان ۱۰۰۰ نمونه و پوشش واقعی بخش‌های سند را اضافه می‌کند. موارد بررسی‌نشده، مبهم یا کامنت‌نشده حذف بی‌صدا نمی‌شوند. نسخهٔ ۲.۰.۱ نیز نام فایل یونیکد، تفکیک خطای ارتباط بله و اعلام شکست PDF ناخوانا را اصلاح کرده بود؛ این حفاظت‌ها حفظ شده‌اند.

[راهنمای به‌روزرسانی سرویس Render و بررسی نسخهٔ آنلاین](docs/DEPLOYMENT.md)

```powershell
$env:BALE_SKIP_DOTENV='1'
python -B -m unittest discover -s tests -v
python -B run_benchmark.py --output docs/benchmark_results.json
Remove-Item Env:BALE_SKIP_DOTENV
```

پرچم BALE_SKIP_DOTENV فقط برای آزمون است؛ پیش از اجرای واقعی ربات باید از محیط حذف شود تا .env خوانده شود.

آزمون‌های ارتباط با بله با mock اجرا می‌شوند و پیام واقعی نمی‌فرستند. مجموعهٔ بنچمارک کوچک و مصنوعی است و برآورد دقت روی پایان‌نامه‌های واقعی نیست.

Dockerfile با کاربر غیر root اجرا می‌شود؛ .dockerignore و COPY محدود، ورود .env، تاریخچهٔ Git و نسخه‌های پشتیبان به تصویر را کنترل می‌کنند. مسیر `/health` زنده‌بودن فرایند و `/ready` تازگی ارتباط موفق با بله را نشان می‌دهد. PORT سرویس سلامت را فعال می‌کند. فایل systemd نمونه به کاربر virastar، مسیر /opt/virastar و فایل محیط /etc/virastar/virastar.env نیاز دارد؛ قبل از استفاده آن‌ها را آماده کنید.

## حریم خصوصی و محدودیت‌ها

پردازش قواعد روی میزبان ربات انجام می‌شود و سرویس مدل زبانی خارجی فراخوانی نمی‌شود؛ انتقال فایل و گزارش از بله می‌گذرد. پاک‌سازی فایل موقت شامل نسخه‌های بله یا میزبان نیست و توقف ناگهانی سیستم می‌تواند پاک‌سازی عادی را ناقص کند. KEEP_ALIVE_URL پیش‌فرض خاموش است.

فایل اصلی پس از پردازش از مسیر موقت پاک می‌شود. گزارش آخرین بررسی شامل شاهدهایی از متن است و حداکثر مدت اعلام‌شده در حافظه نگهداری می‌شود؛ `/forget` آن را حذف می‌کند. اگر بررسی دیگری در حال اجرا باشد، گزارش جدید پس از پایان آماده می‌شود. تحویل در حال اجرا ممکن است هم‌زمان با حذف کامل شود و نسخه‌های قبلاً ارسال‌شده در بله با این دستور حذف نمی‌شوند.

فرمول‌های Office Math، تغییرات ردگیری‌شده، ترتیب ستون PDF و استخراج بدون خطای نمادها تضمین نمی‌شوند. شمارهٔ صفحهٔ Word از شمارهٔ پاراگراف ساخته نمی‌شود. محل پیچیده یا نامطمئن کامنت نمی‌گیرد. شیوه‌نامهٔ دانشگاه، تلفظ‌های متغیر و نام‌های تخصصی ناشناخته همچنان به بازبینی انسانی نیاز دارند. مجموعهٔ مرجع مستقل با برچسب انسانی برای ارزیابی جامع همهٔ قواعد هنوز فراهم نیست.
