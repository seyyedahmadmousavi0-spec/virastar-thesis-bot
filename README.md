# ویراستار پژوهش — نسخهٔ ۲.۵.۰

ربات بله و ابزار خط فرمان برای بازبینی غیرمخرب اسناد پژوهشی فارسی و انگلیسی. سامانه متن را بازنویسی نمی‌کند؛ یافته، شاهد، محل و پیشنهاد بازبینی ارائه می‌دهد. نتیجهٔ این بررسی تأیید صحت علمی یا تضمین نبود خطا نیست.

## قابلیت‌ها

- تحلیل Word شامل متن اصلی، جدول‌های تو‌در‌تو، سرصفحه و پاصفحه، پاورقی و پی‌نوشت، و متن‌کادرهای قابل استخراج؛ همراه با شناسهٔ بلوک و مسیر XML.
- بررسی صفحه‌به‌صفحهٔ PDF؛ متن کوتاه حذف نمی‌شود و صفحات بدون متن یا مشکوک جداگانه مشخص می‌شوند. OCR انجام نمی‌شود.
- قواعد فارسی، نگارش دانشگاهی، انگلیسی و سازگاری ارجاع، با تفکیک اطمینان بالا، بازبینی و ابهام؛ اطمینان یک احتمال آماری نیست.
- حفاظت از اعداد، واحدهای مرکب، فرمول، نماد، DOI، نشانی ایمیل و کد؛ نرمال‌سازی فقط برای تحلیل و با نگاشت به متن اصلی است.
- گزارش HTML آفلاین با جست‌وجو، فیلتر و چاپ، و خروجی JSON، CSV و متن. CSV در برابر اجرای فرمول از متن منبع محافظت می‌شود.
- خروجی پیش‌فرض Word با هایلایت زرد و کامنت کوتاه در محل دقیق یا، برای ایراد قالب‌بندی، در سطح پاراگراف مشخص؛ منبع و شیء سند فراخواننده بازنویسی نمی‌شوند.
- خلاصهٔ کوتاه A/B/C و تعداد واقعی کامنت‌های دقیق، پاراگرافی و ارجاعی؛ دامنهٔ هر کامنت مشخص است.
- بدون سقف جداگانهٔ تعداد کامنت در حالت پیش‌فرض، با پشتیبانی از چند ایراد هم‌پوشان در یک عبارت؛ اولویت سراسری A سپس B است.
- همهٔ یافته‌های تولیدشده در همان Word «نسخهٔ بازبینی» به متن موجود متصل می‌شوند؛ صفحه، بخش یا متن تازه به سند اضافه نمی‌شود. موارد بدون شاهد دقیق، کامنت ارجاعی با توضیح دامنه دارند و موارد C با برچسب بررسی دستی می‌آیند.
- صف محدود مشترک برای متن و فایل، تثبیت حالت در زمان ثبت درخواست، کنترل درخواست تکراری و توقف مرتب.
- بررسی امضای فایل، بودجهٔ ZIP/XML و متن، تعداد یافته‌ها، مسیر خروجی و هش ورودی.
- پروفایل مستقل دانشگاه کاشان با انتخاب ارشد/دکتری و دامنهٔ سند کامل/بخشی از سند، بر پایهٔ راهنمای سه‌صفحه‌ای تحصیلات تکمیلی و الگوهای رسمی بهمن ۱۳۹۸: ترتیب صفحه‌ها، صفحه‌های عنوان، قلم و اندازه، حاشیه، کلیدواژه، شماره‌گذاری صفحه و منابع بند به بند بررسی می‌شوند.

## اجرا

Python 3.12 یا جدیدتر و وابستگی‌های requirements.txt لازم‌اند. آزمون محلی این تغییرات با Python 3.14.6 انجام شده است؛ اجرای ماتریس CI به محیط GitHub وابسته است.

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
```

فایل .env.example را به .env کپی و BALE_TOKEN را با توکن خود تنظیم کنید. سپس:

```powershell
.venv\Scripts\python bot.py
```

Linux:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python bot.py
```

فایل Word را بفرستید؛ یک کپی «نسخهٔ بازبینی» بدون نیاز به `/annotate` برمی‌گردد و همهٔ یافته‌های تولیدشده داخل همین فایل کامنت و هایلایت زرد دارند. محل دقیق یا پاراگراف قابل تأیید در خود متن مشخص می‌شود. برای موردهایی مثل نبودن یک بخش یا محل نامطمئن، کامنت به متن موجود مرتبط یا به محل ارجاع در سطح سند وصل می‌شود و صریح می‌گوید عبارت زردشده لزوماً خطا یا محل دقیق ایراد نیست. موارد مبهم نیز برچسب بررسی دستی دارند. هیچ صفحه، بخش یا متن تازه به سند اضافه نمی‌شود؛ فایل ورودی تغییر نمی‌کند و پیشنهادها در متن علمی اعمال نمی‌شوند. `/comments` راهنمای دیدن کامنت‌ها و `/report` گزارش کامل HTML و TXT آخرین بررسی شما را می‌فرستد. برای یک قالب از `/report html` یا `/report txt` و برای حذف گزارش نگهداری‌شده از `/forget` استفاده کنید. PDF به‌صورت پیش‌فرض گزارش متنی صفحه‌دار دارد.

دستورات انتخاب حالت در ربات: `/thesis`، `/kashan`، `/article` و `/english`. پروفایل دانشگاه علوم پزشکی تهران از ربات برداشته شده و فقط در خط فرمان (`--mode tums`) در دسترس است. `/feedback` پیام کاربر را بدون شناسهٔ او در `feedback.jsonl` ثبت می‌کند و اگر `ADMIN_CHAT_ID` تنظیم شده باشد، برای مالک ربات در بله هم می‌فرستد. انتخاب حالت در زمان ثبت درخواست حفظ می‌شود، حتی اگر در زمان انتظار حالت را تغییر دهید. `/settings` محدودیت‌ها، `/privacy` نگهداری داده و `/help` راهنما را نشان می‌دهد.

دانشگاه کاشان: دکمهٔ **«🏛 دانشگاه کاشان»** یا `/kashan` را بزنید؛ کارشناسی ارشد یا دکتری و سپس دامنهٔ سند را انتخاب کنید. انتخاب مستقیم با `/kashan_master` و `/kashan_phd` نیز ممکن است. پیش‌فرض اولیه محافظه‌کارانه «بخشی از سند» است؛ برای بررسی یک پایان‌نامهٔ کامل، `/scope full` و برای یک فصل یا چکیده `/scope part` را بزنید. مقطع و دامنه در زمان ثبت درخواست ثابت می‌مانند. `/part` در توضیح فایل فقط همان فایل را جزئی بررسی می‌کند. `/kashan_info` منشأ و محدودیت‌ها را توضیح می‌دهد.

پروفایل کاشان با قواعد عمومی و TUMS ترکیب نمی‌شود. مبنای آن راهنمای سه‌صفحه‌ای تحصیلات تکمیلی و الگوهای رسمی ارشد و دکتری (بهمن ۱۳۹۸) است: متن نازنین یا لوتوس ۱۲، زیرنویس ۱۰، عنوان‌ها تیتر ۱۶/۱۴/۱۲، حاشیهٔ ۳ سانتی‌متر، ۴ یا ۵ کلیدواژه، بدون شماره پیش از فهرست مطالب و حروف ابجد از آن. تقدیم اختیاری است و تعداد فصل‌ها و نسخهٔ APA تعیین نمی‌شوند. چیدمان دیداری، امضاها، CD و ایرانداک در چک‌لیست بررسی دستی می‌آیند. ## خط فرمان و گزارش‌ها

```powershell
python checker.py thesis.docx --mode thesis --output-dir reports
python checker.py article.pdf --mode article --format json
python checker.py paragraph.txt --text --mode english --output-dir reports
python checker.py thesis.docx --annotate reviewed.docx
python checker.py thesis.docx --annotate reviewed.docx --word-report all-findings.docx
python checker.py thesis.docx --annotate reviewed.docx --max-comments 100
python checker.py article.pdf --annotate-pdf reviewed.pdf --output-dir reports
python checker.py thesis.docx --mode kashan_master --scope full --annotate reviewed.docx --output-dir reports
python checker.py chapter.docx --mode kashan_phd --scope fragment --output-dir reports
python checker.py --list-rules
python checker.py --version
```

پوشهٔ خروجی شامل report.html، report.json، report.csv و report.txt است. مسیر خروجی نمی‌تواند همان ورودی یا پیوندی به آن باشد. `--rules custom-rules.json` قواعد سفارشی، `--include-ambiguous` نمایش ابهام و `--fail-on A` کد خروج مناسب خودکارسازی را فراهم می‌کند. کد خروج ۰ موفقیت، ۱ یافتهٔ سطح انتخابی و ۲ خطای پردازش است.

`--annotate` همهٔ یافته‌های تولیدشده را در همان کپی Word با کامنت و زرد مشخص می‌کند و متن یا پاراگرافی نمی‌افزاید. سقف جداگانهٔ پاراگراف وجود ندارد. `--max-comments N` فقط سقف اختیاری ۰ تا ۱۰۰۰۰ برای کامنت دقیق یا پاراگرافی است؛ باقی یافته‌ها حذف نمی‌شوند و با کامنت ارجاعیِ دارای توضیح دامنه به متن موجود متصل می‌شوند. در خط فرمان مقدار ۰ همهٔ یافته‌ها را به صورت ارجاعی درج می‌کند. `--word-report all-findings.docx` همچنان گزینهٔ اختیاری برای ساخت یک گزارش مستقل اضافی است و برای کامل‌بودن `--annotate` لازم نیست. مسیرهای خروجی باید از ورودی و از یکدیگر مستقل باشند.

`--annotate-pdf` آزمایشی است: فقط شاهدی با نگاشت دقیق نویسه و مختصات نشانه‌گذاری می‌شود. آزمون‌های متن شکل‌یافتهٔ فارسی، نیم‌فاصله، اعراب، متن دوزبانه، تکرار، ستون و چرخش انجام می‌شوند؛ نمایش یادداشت فارسی در PDFخوان‌های مستقل هنوز تأیید نشده است. برای ربات، `PDF_ANNOTATION_EXPERIMENTAL=0` پیش‌فرض می‌ماند و گزارش متنی صفحه‌دار حفظ می‌شود.

[نمونهٔ محلی گزارش HTML با دادهٔ مصنوعی](docs/demo/report.html) · [گزارش کامل ارتقا](docs/PROFESSIONAL_UPGRADE.md)

برای ساخت بستهٔ کد بدون .env، اسناد عملیاتی، تاریخچهٔ Git و پشتیبان‌ها، `python package_release.py` را اجرا کنید. فایل ZIP در dist ساخته می‌شود و manifest هش دارد. نمونه‌های اسنادی demo و PDF شیوه‌نامه به بستهٔ کد وارد نمی‌شوند.

## پیکربندی

مقادیر محیطی در .env.example توضیح داده شده‌اند. MAX_QUEUE تعداد انتظار علاوه بر WORKERS است. تعداد کل درخواست‌های ثبت‌شده از مجموع این دو بیشتر نمی‌شود. هیچ فایل یا متن کاربری در لاگ یا پاسخ سلامت قرار نمی‌گیرد.

`MAX_COMMENTS=0` پیش‌فرض ربات است و سقف تعداد برای کامنت دقیق یا پاراگرافی ندارد؛ عدد مثبت ۱ تا ۱۰۰۰۰ سقف اختیاری مدیر میزبان برای همین محل‌هاست. در مسیر ربات سقف جداگانهٔ پاراگراف فعال نیست. تمام موارد باقی‌مانده با کامنت ارجاعی و توضیح دامنه، روی متن موجود همان Word قرار می‌گیرند. بودجهٔ تحلیل سند همچنان برقرار است و رسیدن به آن با هشدار محدودیت اعلام می‌شود؛ «همه» به معنی همهٔ یافته‌های تولیدشده است، نه تضمین کشف تمام خطاهای متن. گزارش کامل Word حداکثر ۱۰۰۰۱ مدخل و ۲۵ مگابایت دارد؛ ناتوانی در تولید کامل آن صریح اعلام می‌شود و خروجی ناقص جای گزارش کامل منتشر نمی‌شود.

`FOLD_REPEATED_COMMENTS=3`: یک ایراد یکسان (همان قاعده و همان متن) فقط در سه محل نخست کامنت جدا می‌گیرد؛ تکرارهای بعدی در محل خود زرد می‌شوند و کامنت نخستین مورد تعداد کل و پیشنهاد اصلاح یک‌جا با Find & Replace را می‌گوید. در آزمون، پایان‌نامه‌ای ۱۰۵ صفحه‌ای با ۹۰۰۸ یافته از ۳ دقیقه به ۱۰ ثانیه برای باز شدن در Word رسید. مقدار ۰ برای هر یافته کامنت جدا می‌سازد؛ در خط فرمان معادل آن `--comment-every-finding` است.

`REPORT_TTL_MINUTES=15`، `REPORT_CACHE_MB=32` و سقف داخلی ۶۴ گزارش/۸ مگابایت برای هر گزارش، نگهداری را محدود می‌کنند. فقط HTML و TXT در حافظه نگهداری می‌شوند و دسترسی به ترکیب فرستنده و گفت‌وگو محدود است. فایل Word ورودی و نسخهٔ بازبینی در این حافظه نگهداری نمی‌شوند. بررسی جدید جای گزارش قبلی همان فرستنده را می‌گیرد. گزارش منقضی قابل دریافت نیست؛ پاک‌سازی حافظه هر ۳۰ ثانیه انجام می‌شود. پرشدن ظرفیت یا راه‌اندازی مجدد ممکن است گزارش را زودتر پاک کند. اگر گزارش بزرگ‌تر از ظرفیت باشد، همان لحظه ارسال می‌شود تا نتیجه بی‌صدا از دست نرود.

قواعد در rules.json و پروفایل دانشگاه در profiles/tums.json نگهداری می‌شوند. کلیدهای اختیاری:

| کلید | پیش‌فرض | کاربرد |
|---|---:|---|
| strict | true | خودداری از نمایش عادی موارد مبهم |
| protected_terms | [] | نام و اصطلاح تخصصی که نباید پیشنهاد عمومی دریافت کند |
| disabled_rules | [] | شناسهٔ قواعد غیرفعال، در همهٔ خروجی‌های تحلیل |
| max_input_bytes | 26214400 | سقف اندازهٔ ورودی |
| max_document_chars | 4000000 | بودجهٔ متن سند |
| max_document_blocks | 25000 | بودجهٔ بلوک‌های Word |
| max_analysis_block_chars | 200000 | بودجهٔ هر بلوک قواعد |
| max_findings_per_block | 500 | سقف یافتهٔ هر بلوک، همراه هشدار محدودیت |
| max_findings | 10000 | سقف یافتهٔ سند، همراه هشدار محدودیت |
| max_pdf_pages | 1000 | بودجهٔ صفحات PDF |

کلیدهای متنی/اندازه‌ای مهم هنگام بارگذاری اعتبارسنجی می‌شوند. تنظیمات سفارشی باید ساختار کامل قواعد پایه را حفظ کنند. حذف یک هشدار از خروجی به معنی درست‌بودن متن نیست.

## آزمون و استقرار

نسخهٔ ۲.۱ خروجی پیش‌فرض Word، گزارش اختیاری با دسترسی محدود، کامنت‌های کوتاه و اولویت‌دار، گزارش کامل بدون سقف پنهان ۱۰۰۰ نمونه و پوشش واقعی بخش‌های سند را اضافه می‌کند. موارد بررسی‌نشده، مبهم یا کامنت‌نشده حذف بی‌صدا نمی‌شوند. نسخهٔ ۲.۰.۱ نیز نام فایل یونیکد، تفکیک خطای ارتباط بله و اعلام شکست PDF ناخوانا را اصلاح کرده بود؛ این حفاظت‌ها حفظ شده‌اند.

نسخهٔ ۲.۲ انتخاب کاشان، چک‌لیست مستند ارشد/دکتری، بازبینی محافظه‌کارانهٔ عنوان مقطع و منابع، و تفکیک بخش قابل بررسی از تأیید انسانی را اضافه می‌کند. هیچ قلم، اندازه، حاشیه، طول چکیده، تعداد کلیدواژه یا تعداد فصل از مقادیر نمونهٔ عمومی به قانون کاشان تبدیل نمی‌شود.

نسخهٔ ۲.۳ سقف پیش‌فرض تعداد کامنت را برمی‌دارد، چند کامنت روی عبارت‌های هم‌پوشان و کامنت قالب‌بندی در سطح پاراگراف را پشتیبانی می‌کند و برای یافته‌های بدون محل امن در متن، گزارش مستقل Word شامل همهٔ موارد با کامنت و عنوان زرد می‌فرستد. کامنت دقیق، کامنت پاراگرافی و مدخل گزارش مستقل با شمارش جداگانه اعلام می‌شوند.

نسخهٔ ۲.۳.۱ مسیر یک Word همراه بخش پایانی را آزمایش کرد؛ این رفتار در نسخهٔ ۲.۳.۲ جایگزین شد. نسخهٔ ۲.۳.۲ همهٔ یافته‌های تولیدشده را به متن موجود همان کپی متصل می‌کند، بدون افزودن صفحه یا بخش جدید. کامنت ارجاعی برای موارد بدون شاهد دقیق، دامنه و عدم قطعیت را صریح اعلام می‌کند. شمارش نهایی کامل‌بودن پوشش یافته‌های تولیدشده را کنترل می‌کند؛ فایل ورودی و متن علمی آن بازنویسی نمی‌شوند.

نسخهٔ ۲.۴ ارقام لاتین و عربیِ تنها در متن فارسی را نیز می‌یابد (اعداد همراه واحد، فرمول، آمار و ارجاع همچنان محافظت می‌شوند)، شناسهٔ جدای فعل («کرده اند») و پسوند چسبیده به «ه» پایانی («دادهها») را گزارش می‌کند و برای قواعد فاصله‌گذاری و نشانه‌ها صورت اصلاح‌شدهٔ دقیق را در کامنت پیشنهاد می‌دهد. هر جدول بدون عنوان روی پاراگراف پیش از خود و ایراد حاشیه و اندازهٔ صفحه روی آغاز همان بخش سند کامنت می‌گیرد. ایراد قالب‌بندی‌ای که در بیش از سه پاراگراف تکرار شود، یک کامنت با شمار و شمارهٔ پاراگراف‌ها می‌شود تا سند با صدها کامنت یکسان پر نشود. پیام‌های ارجاع، انگلیسی و حاشیهٔ TUMS فارسی شده‌اند و عنوان‌های کاشان با «ـهٔ»، «ۀ» و «ـه‌ی» درست تطبیق داده می‌شوند. پیکرهٔ برچسب‌دار `tests/test_precision_corpus.py` نبود هشدار کاذب روی متن درست و کشف همهٔ خطاهای کاشته‌شده را کنترل می‌کند؛ این پیکره مصنوعی است و برآورد دقت روی همهٔ پایان‌نامه‌ها نیست.

نسخهٔ ۲.۴ همچنین غلط‌یاب املایی فارسی دارد (`fa_spell.py`، واژه‌نامهٔ hazm با مجوز MIT در `lexicon/`). واژه فقط وقتی گزارش می‌شود که پس از حذف پسوندها و صرف فعل در واژه‌نامه نباشد، دست‌کم چهار حرف داشته باشد، در کل سند بیش از دو بار تکرار نشده باشد و دقیقاً یک واژهٔ پرکاربرد با یک خطای تایپی واقعی (کلید مجاور، نقطه، جاافتادن، جابه‌جایی یا تکرار حرف) از آن فاصله داشته باشد. روی ۷۵۶۷ واژهٔ متن واقعی فارسی ۲ هشدار کاذب (دو وام‌واژهٔ فنی انگلیسی) و روی غلط‌های تایپی ساختگی کشف ۷۸٪ با پیشنهاد درست در ۹۱٪ موارد اندازه‌گیری شد. املا در PDF به‌دلیل خطای استخراج نویسه بررسی نمی‌شود؛ نقل‌قول‌ها، ارجاع‌ها و `protected_terms` مستثنا هستند. بررسی‌های سراسری `structure_checks.py` منبع بدون ارجاع در متن، یک واژه با دو املای پیوسته و نیم‌فاصله‌دار، و جدول/شکلی که در متن به آن ارجاع داده نشده را گزارش می‌کنند و اگر شیوهٔ ارجاع سند قابل فهم نباشد، چیزی نمی‌گویند. فهرست غلط‌های رایج با همزه («تأثیر»، «مؤثر»)، تنوین («کاملاً») و پیوسته/جدانویسی گسترش یافته است. بررسی یک پایان‌نامهٔ ۵۰ هزار واژه‌ای با ساخت Word کامنت‌دار حدود ۱۱ ثانیه طول می‌کشد. پیام آغاز و راهنمای ربات کوتاه‌تر و مرحله‌به‌مرحله شده‌اند، خلاصهٔ نتیجه یافته‌ها را بر اساس موضوع (املا، سبک، ارجاع، صفحه‌آرایی، ساختار) می‌شمارد و نام سازنده در آغاز و راهنما آمده است.

[راهنمای به‌روزرسانی سرویس Render و بررسی نسخهٔ آنلاین](docs/DEPLOYMENT.md)

```powershell
$env:BALE_SKIP_DOTENV='1'
python -B -m unittest discover -s tests -v
python -B run_benchmark.py --output docs/benchmark_results.json
Remove-Item Env:BALE_SKIP_DOTENV
```

پرچم BALE_SKIP_DOTENV فقط برای آزمون است؛ پیش از اجرای واقعی ربات باید از محیط حذف شود تا .env خوانده شود.

آزمون‌های ارتباط با بله با mock اجرا می‌شوند و پیام واقعی نمی‌فرستند. مجموعهٔ بنچمارک کوچک و مصنوعی است و برآورد دقت روی پایان‌نامه‌های واقعی نیست.

Dockerfile با کاربر غیر root اجرا می‌شود؛ .dockerignore و COPY محدود، ورود .env، تاریخچهٔ Git و نسخه‌های پشتیبان به تصویر را کنترل می‌کنند. مسیر `/health` زنده‌بودن فرایند و `/ready` تازگی ارتباط موفق با بله را نشان می‌دهد. PORT سرویس سلامت را فعال می‌کند. فایل systemd نمونه به کاربر virastar، مسیر /opt/virastar و فایل محیط /etc/virastar/virastar.env نیاز دارد؛ قبل از استفاده آن‌ها را آماده کنید.

## حریم خصوصی و محدودیت‌ها

پردازش قواعد روی میزبان ربات انجام می‌شود و سرویس مدل زبانی خارجی فراخوانی نمی‌شود؛ انتقال فایل و گزارش از بله می‌گذرد. پاک‌سازی فایل موقت شامل نسخه‌های بله یا میزبان نیست و توقف ناگهانی سیستم می‌تواند پاک‌سازی عادی را ناقص کند. KEEP_ALIVE_URL پیش‌فرض خاموش است.

فایل اصلی پس از پردازش از مسیر موقت پاک می‌شود. گزارش آخرین بررسی شامل شاهدهایی از متن است و حداکثر مدت اعلام‌شده در حافظه نگهداری می‌شود؛ `/forget` آن را حذف می‌کند. اگر بررسی دیگری در حال اجرا باشد، گزارش جدید پس از پایان آماده می‌شود. تحویل در حال اجرا ممکن است هم‌زمان با حذف کامل شود و نسخه‌های قبلاً ارسال‌شده در بله با این دستور حذف نمی‌شوند.

فرمول‌های Office Math، تغییرات ردگیری‌شده، ترتیب ستون PDF و استخراج بدون خطای نمادها تضمین نمی‌شوند. شمارهٔ صفحهٔ Word از شمارهٔ پاراگراف ساخته نمی‌شود. در محل پیچیده یا نامطمئن، کامنت ارجاعی روی متن موجود صریح می‌گوید عبارت زردشده محل دقیق ایراد نیست؛ این ارجاع شاهد دقیق خطا محسوب نمی‌شود. سند خالی یا بدون هیچ متن قابل اتصال امن ممکن است Word کامل نسازد؛ این شکست صریح اعلام می‌شود. شیوه‌نامهٔ دانشگاه، تلفظ‌های متغیر و نام‌های تخصصی ناشناخته همچنان به بازبینی انسانی نیاز دارند. مجموعهٔ مرجع مستقل با برچسب انسانی برای ارزیابی جامع همهٔ قواعد هنوز فراهم نیست.
