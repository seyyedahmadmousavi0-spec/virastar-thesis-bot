# گزارش نسخهٔ محلی ۲ ویراستار پژوهش

تاریخ: ۲۰ اکتبر ۲۰۲۶. این گزارش وضعیت کد محلی را توصیف می‌کند. هیچ سرور زنده، ربات بله، تنظیم استارتاپ یا سرویس سیستم‌عامل در این نوبت فعال یا منتشر نشد.

## نتیجهٔ اصلی

پروژه از یک بررسی‌کننده با گزارش متنی به مسیر بازبینی ساختارمند و قابل ممیزی ارتقا یافته است: استخراج بلوک‌های منبع، قواعد محتاطانه، شواهد اصلی، محدودیت منابع، گزارش چندقالبی و خروجی اختیاری Word. فایل ورودی برای ذخیره‌سازی باز نمی‌شود و تغییر احتمالی آن با هش کنترل می‌شود.

نمونهٔ مصنوعی در پوشهٔ demo شامل گزارش HTML، JSON، CSV، متن، Word اصلی و کپی کامنت‌گذاری‌شده است. نمونه‌ها صرفاً برای نمایش‌اند و هیچ پایان‌نامهٔ واقعی وارد آزمون نشده است. بستهٔ ZIP کد، فایل‌های عملیاتی کاربران و نسخه‌های پشتیبان را شامل نمی‌شود.

## ممیزی و تصمیم‌ها

مبنای این مرحله، نسخهٔ قبلی با ۶۸ آزمون موفق و تغییرات ثبت‌نشدهٔ موجود بود. آن تغییرات حفظ شدند. نسخهٔ پشتیبان پیش از این مرحله در `upgrade_backup/professional_20261020_180451/` ذخیره شد. اختلاف Git با HEAD شامل کارهای قبل از این مرحله هم هست.

در حین کار، پرشدن درایو C یک نوشتن را ناقص کرد. تغییرنویسی متوقف شد، checker.py از پشتیبان سالم بازیابی شد، و پس از آزادشدن فضا یکپارچگی و نحو فایل‌ها دوباره بررسی شد. کارهای بعدی با آزمون کامل تأیید شدند. هیچ فایل شخصی برای آزادکردن فضا حذف نشد؛ فقط کش قابل‌بازتولید Python همین پروژه پاک شد.

## معماری و قرارداد خروجی

دریافت → اعتبارسنجی نوع و بودجه → کپی کار مستقل → استخراج بلوک‌های منبع → حفاظت علمی و قواعد → اعتبار شاهد و سطح اطمینان → گزارش و خروجی اختیاری.

Issue قرارداد قدیمی را حفظ می‌کند و فیلدهای منبع به انتهای آن اضافه شده‌اند. `auto_applied` همواره false است. original_text فقط وقتی ارائه می‌شود که شاهد واقعاً به محل خود در متن منبع متصل باشد. شناسهٔ نتیجه از منبع و مشخصات یافتۀ مربوط ساخته می‌شود. schema_version گزارش JSON برابر 2.0 است و هش تنظیمات برای ممیزی ثبت می‌شود؛ خود تنظیمات و مسیر محلی فایل در گزارش ماشینی کپی نمی‌شوند.

اطمینان A، B و C احتمال یا درصد موفقیت نیست. A به شواهد محلی قوی‌تر، B به بازبینی بافت و C به ابهام اشاره می‌کند. registry سقف اطمینان و نسخهٔ قواعد را مشخص می‌کند. C در گزارش عادی Strict مخفی است و در خروجی ماشینی با برچسب خود باقی می‌ماند. غیرقطعی‌بودن نتیجه و کیفیت استخراج پنهان نمی‌شود.

## شواهد اعتبارسنجی

- آخرین مجموعهٔ کامل محلی: **۱۴۱ آزمون موفق، بدون شکست و بدون skip**؛ ۷۳ آزمون بیشتر از مبنای این مرحله.
- نحو **۲۹ فایل Python** بررسی شد. محیط اجرا Windows و Python 3.14.6 بود؛ وابستگی جدیدی به requirements.txt افزوده نشد.
- تست‌های ربات شامل ظرفیت، رزرو، لغو درخواست منتظر، خطای submit، mode، API، سلامت و shutdown با mock هستند. هیچ پیام واقعی فرستاده نشد.
- تست‌های سند شامل ساختار تو‌در‌تو، فیلد، یادداشت، متن‌کادر، کامنت با نام غیرمعمول، شاهد نادرست، تغییر شیء سند، alias خروجی، DTD و XML UTF-16 هستند.
- تست‌های گزارش شامل XSS، CSV، انتشار اتمی، محرمانگی metadata و اجرای اسکریپت واقعی جست‌وجو/فیلتر/چاپ در محیط DOM شبیه‌سازی‌شده‌اند.
- مرورگر متصل برای بررسی بصری در دسترس نبود؛ آزمون شبیه‌سازی‌شده جای بررسی بصری در مرورگر واقعی را نمی‌گیرد.
- بنچمارک **۲۶ متن مصنوعی**، برای ۱۴ قاعدهٔ هدف: هر قاعده TP=1، FP=0، FN=0، TN=12 دارد. Precision و Recall نمونه‌ای ۱ هستند، اما فقط یک مثبت برای هر قاعده وجود دارد. این نتیجه برای اعلام دقت عمومی کافی نیست.
- بنچمارک ۷ تشخیص بازبینی و یک تشخیص اضافی بدون برچسب در داده‌های مثبت دارد. پیشنهادهای info روی منفی‌ها برچسب‌گذاری نشده و FP این سنجش محسوب نمی‌شوند. داده‌ها تأیید انسانی مستقل ندارند. جزئیات در benchmark_results.json است.
- ماتریس CI برای Windows/Linux و Python 3.12/3.14 تعریف شده است؛ اجرای واقعی آن در GitHub و ساخت Docker در این نوبت انجام نشده‌اند.

| فرهنگ تخصصی حوزه‌های دانشگاهی | protected_terms و قواعد غیرفعال قابل تنظیم‌اند؛ شناسایی عمومی همهٔ نام‌ها ادعا نمی‌شود |

| ذخیرهٔ پایدار تنظیمات کاربران و پنل مدیریت | اضافه نشد؛ طراحی آن باید حداقل‌سازی اطلاعات و کنترل دسترسی را روشن کند |

شمارهٔ صفحهٔ Word از پاراگراف استنتاج نمی‌شود. بررسی قالب بر پروفایل محلی تکیه دارد و به معنی تأیید آخرین شیوه‌نامه نیست. پایایی نمادها و ترتیب PDF قطعی نیست. خودداری از پیشنهاد یا کامنت در محل پیچیده می‌تواند منفی کاذب را بیشتر کند. رکوردهای کتابشناختیِ چندپاراگرافی و نام‌های پیچیده همچنان محدودیت دارند.

کنترل هش تغییر فایل را کشف می‌کند و قفل سیستم‌عامل در برابر برنامهٔ خارجی نیست. محدودیت ZIP ممکن است فایل سالمِ بسیار فشرده را هم رد کند. پاک‌سازی موقت در توقف ناگهانی سیستم تضمین نمی‌شود و نسخه‌های بله و میزبان خارج از کنترل پاک‌سازی محلی‌اند. workflow قدیمی keep_alive.yml با مقصد قبلی کاربر در این نوبت دست‌نخورده مانده است؛ keep-alive داخل برنامه پیش‌فرض خاموش است.

## اجرا و تحویل

```powershell
python -B -m unittest discover -s tests -v
python -B run_benchmark.py --output docs/benchmark_results.json
python checker.py thesis.docx --mode thesis --output-dir reports
python checker.py thesis.docx --annotate reviewed.docx
python checker.py --list-rules
python package_release.py
```

بستهٔ محلی در dist/virastar-professional-2.0.0.zip ساخته می‌شود و release-manifest.json آن اندازه و SHA-256 هر فایل را ثبت می‌کند. نمونه‌های اسنادی demo و PDF شیوه‌نامه در بستهٔ کد قرار نمی‌گیرند. انتقال یا انتشار این بسته انجام نشده است.

برای بازگشت، ابتدا تغییرات بعدی خود را جدا ذخیره کنید و فایل‌های هم‌نام نسخهٔ پشتیبان professional_20261020_180451 را کپی کنید. launcherها هم در پشتیبان موجودند. فایل‌های تازهٔ این مرحله را در صورت نیاز به پوشه‌ای بیرون از مسیر کشف آزمون منتقل کنید. ماژول‌هایی که از مرحلهٔ قبلی ثبت‌نشده بودند نباید با git clean یا git reset --hard حذف شوند. نسخهٔ پشتیبان شامل تغییرات ثبت‌نشدهٔ پیشین شماست.
